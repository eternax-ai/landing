How does EternaX Bitcoin Vault work?

Each vault is a standard Bitcoin address built from 100 fresh keys that must all sign, used exactly once. The method is called One-Time Vaulting; at 100 keys it is the 100-Key Vault, written OTV(100).

  1. 1

    Hold behind a hash

    Coins sit in a one-time address built from 100 fresh keys in your HSM. The chain sees only a SHA-256 hash, so there is nothing for a quantum computer to attack.

  2. 2

    Approve with post-quantum signatures

    Your officers approve one exact transaction with SLH-DSA or ML-DSA. Independent signing systems, including one you run, check the approvals before signing.

  3. 3

    Spend once, re-vault

    The 100 signatures go out in one ordinary transaction. Change moves to a fresh vault, and the old keys are retired after six confirmations.

Why 100 keys is enough, and for how long

A first fast quantum computer would need about nine minutes to break one Bitcoin key, and a block arrives in about ten. To steal a vault spend, an attacker must break all 100 keys before that block.

EternaX Bitcoin Vault uses only standard Bitcoin features in use since 2017, stays within the 100-key limit that Bitcoin’s standard relay policy allows per input, and approves spends with NIST-standard SLH-DSA and ML-DSA signatures. A 100-key spend was confirmed on Bitcoin mainnet in block 973,546. Prototype tests and an internal security review are complete, the method is published, and the security model is shared under NDA during the pilot.

100 is the most keys a single standard Bitcoin input can carry: Bitcoin Core’s relay policy allows a 3,600-byte witness script and 100 witness items per P2WSH input. Each extra key forces an attacker to derive one more private key inside the same block, so 100 keys gives EternaX Bitcoin Vault the most protection that still relays as an ordinary transaction.

The attacker must derive all 100 private keys after the transaction is broadcast and before the next block, then outbid the fee. On Google Quantum AI’s estimate of about nine minutes per key, even an attacker with seven fast quantum machines would win about 1 in 730,000 spends, against about 41% for an ordinary single-key spend. EternaX Bitcoin Vault pays fees that target the next block to keep that window short.

No single system. In EternaX Bitcoin Vault the 100 keys sit across independent signing systems under separate control, including one the asset owner runs, and each checks the post-quantum approvals against the exact transaction before signing its share. A thief would have to breach all of them, or derive all 100 keys inside one block.

Key backup and recovery is a core capability: keys are backed up through your HSM’s certified backup, so losing a device never means losing bitcoin. Because a vault that needs all 100 keys tolerates no missing key, each institution’s recovery path in EternaX Bitcoin Vault is set during the pilot and documented in the security model it files.

Approvals use NIST-standard post-quantum signatures: SLH-DSA, the hash-based standard in FIPS 205, and ML-DSA, the lattice-based standard in FIPS 204, selected by policy. On-chain, Bitcoin verifies ordinary ECDSA signatures from the 100 vault keys, because that is all Bitcoin accepts today; EternaX Bitcoin Vault adds the post-quantum layer around them.

BIP-360, Pay to Merkle Root, is a draft proposal towards native post-quantum outputs, which also need a post-quantum signature proposal. When Bitcoin activates them, coins in EternaX Bitcoin Vault move across in one ordinary transaction. The vault is a bridge for the years before that upgrade, built to be left behind.
